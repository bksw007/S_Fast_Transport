# Reports Implementation Plan

**Goal:** Replace all four report demo items with operational reports using authorized live jobs.
**Architecture:** Reuse the existing scoped jobs subscription; preserve report fields in the shared model. Pure reporting helpers calculate Bangkok deadlines, filters and grouped metrics; a responsive component renders the four report views and exports the same filtered data.
**Tech Stack:** Next.js, React, TypeScript, Firestore, ExcelJS.

### Task 1: Reporting data and calculations
- Modify `packages/shared/src/index.ts` and both transport repositories to preserve job dates, schedule and actual arrival timestamps.
- Record arrival and completion timestamps in both status writers; retain the first arrival.
- Add `apps/web/lib/reports.ts` and `tests/reports.cjs` covering overdue, cancelled, missing data, boundary dates and grouped results.

### Task 2: Working report UI
- Create `apps/web/app/components/ReportsScreen.tsx` with four views, date/customer/company filters, search, status filters, metrics and grouped tables.
- Connect desktop and mobile Reports branches in `apps/web/app/page.tsx`; use all authorized jobs including completed jobs.
- Add responsive and print styles in `apps/web/app/styles.css`.

### Task 3: Export and validation
- Export filtered detail and summaries to a genuine XLSX workbook; print a standalone report to PDF through the browser print dialog.
- Run reporting tests, existing regression tests, typecheck, lint and production build. Verify UI with representative fixture data and confirm no duplicate report in print output.
